**1. Операции, требующие ввод данных**

1)Регистрация учётной записи.

2)Авторизация пользователей.

3)Создание проекта

4)Изменение проекта

5)Создание задачи.

6)Создание задачи с указанием даты начала и завершения.

7)Изменение задачи.

**2. Описание операций**

**2.1. Регистрация.**

-Назначение: Создание учётной записи пользователя.

-Входные данные: логин, 2 одинаковых пароля.

-Результат: создание записи в таблице с пользователями в базе данных с перенаправлением на страницу авторизации или вывод сообщения о ошибке без действий.

-Используемые SQL-запросы: "INSERT INTO clients(login, password_hash) VALUES (?, ?)".

-Валидация: Проверка на длину логина больше или равной 4 и меньше или равна 100, больше или равной 8 и меньше или равна 10000 для пароля, пароль должен точно содержать буквы и цифры, проверка на совпадение введённых паролей, проверка пароля на не строку только из пробелов.

-Обработка ошибок: Вывод сообщений о ошибке валидации или наличии пользователя с данным логином.

**2.2. Авторизация пользователей**

-Назначение: проверка логина и хэша пароля для доступа к данным пользователя.

-Входные данные: логин, пароль. 

-Результат: создание токена с логином пользователя, запись токена в cookies с перенаправлением на страницу проектов пользователя или вывод сообщения о ошибке без действий.

-Используемые SQL-запросы: "SELECT id, login, password_hash FROM clients WHERE login=?"

-Валидация: Проверка на длину логина больше или равной 4 и до 100, больше или равной 8 и меньше или равна 10000 для пароля, проверка введенного пароля на соответствие хэшу в базе данных.

-Обработка ошибок: ошибка неверного логина или пароля при не нахождении записи в базе данных или несоответствии пароля, ошибка при несоответствии введённых данных условиям валидации.

**2.3. Создание проекта***

-Назначение: создание записи в таблице с проектами в базе данных.

-Входные данные: название проекта, описание (можно оставить пустым), дата проекта(можно оставить пустым, будут использованы текущие дата и время).

-Валидация: длина названия проекта должна быть от 1 до 100 включительно символов, длина описания должна быть от 1 до 10000 включительно символов(если не оставлять пустым), если указана дата создания, то она должна удовлетворять "ДД.ММ.ГГГГ" (можно также указать с временем "ДД.ММ.ГГГГ ЧЧ:ММ"), нельзя создать проект с названием, которое уже есть в таблице с проектами в записях базы данных для текущего пользователя.

-Результат: создание проекта (записи в таблице с проектами в базе данных) с перенаправлением на страницу с проектами пользователя или вывод сообщения о ошибке без действий.

-Используемые SQL-запросы: "SELECT name FROM projects WHERE name=? AND user_id=?" (поиск среди проектов пользователя с данным именем); INSERT INTO projects(name, description, status, created_at, user_id) VALUES (?, ?, 'active', ?, ?)" (Создание с учётом введенного описания проекта);
"INSERT INTO projects(name, description, status, created_at, user_id) VALUES (?, NULL, 'active', ?, ?)" (Создание без учёта описания).

-Обработка ошибок: сообщение о ошибке создания проектаиз-за несоответствия условиям валидации названия, описания или даты, сообщение о ошибке создания при наличии проекта с таким названием у текущего пользователя.

**2.4. Изменение проекта**

-Назначение: изменение записи в таблице с проектами в базе данных.

-Входные данные(в зависимости от выбора изменяемых данных): новое название проекта, обвноленное описание проекта, новая дата создания.

-Валидация. длина названия проекта должна быть от 1 до 100 включительно символов, длина описания должна быть от 1 до 10000 включительно символов, дата создания должна удовлетворять "ДД.ММ.ГГГГ" (можно также указать с временем "ДД.ММ.ГГГГ ЧЧ:ММ"), новое название проекта не должно быть в записях в таблице с проектами для текущего пользователя.

-Результат: Изменение выбранных данных проекта (изменение записи в таблице с проектами в базе данных) с перенаправлением на страницу проектов пользователя или вывод сообщения о ошибке без действий.

-Используемые SQL-запросы: "SELECT user_id FROM projects WHERE id=?" (выбор идентификатора пользователя, которому принадлежит проект); "SELECT name FROM projects WHERE name=? AND user_id=?" (поиск нового названия проекта с идентификатором текущего пользователя, чтобы убедиться, что новое название не используется в проектах пользователя);
"UPDATE projects SET name=? WHERE id=?" (обновление названия); "UPDATE projects SET description=? WHERE id=?" (обновление описания); "UPDATE projects SET created_at=? WHERE id=?" (обновление даты создания).

-Обработка ошибок: сообщение о ошибке изменения проекта из-за несоответствия условиям валидации названия, описания или даты, сообщение о ошибке изменении при наличии проекта с новым названием у текущего пользователя.

**2.5. Создание задачи**

-Назначение: создание новой записи в таблице с задачами в базе данных

-Входные данные. Название задачи, описание (можно оставить пустым), дата создания (можно оставить пустым, будут использованы текущие дата и время).

-Валидация: длина названия задачи должна быть от 1 до 100 включительно символов, длина описания должна быть от 1 до 10000 включительно символов(если не оставлять пустым), если указана дата создания, то она должна удовлетворять "ДД.ММ.ГГГГ" (можно также указать с временем "ДД.ММ.ГГГГ ЧЧ:ММ"), нельзя создать задачу с названием, которое уже есть в таблице с задачами в записях базы данных для текущего проекта.

-Результат: создание задачи с перенаправлением на страницу задач проекта или вывод сообщения о ошибке без действий.

-Используемые SQL-Запросы: "SELECT name FROM tasks WHERE name=? AND project_id=?" (поиск названия задачи текущего проекта, чтобы убедиться, что для проекта нет задачи с данным названием);"INSERT INTO tasks(name, description, status, created_at, project_id) VALUES (?, ?, 'passive', ?, ?)" (добавление с учётом описания); "INSERT INTO tasks(name, description, status, created_at, project_id) VALUES (?, NULL, 'passive', ?, ?)" (добавление без учёта описания);

-Обработка ошибок: сообщение о ошибке создания задачи из-за несоответствия условиям валидации названия, описания или даты, сообщение о ошибке создания задачи при наличии задачи с таким названием у текущего проекта.

**2.6. Создание задачи с указанием даты начала и завершения**

-Назначение: Создание задачи с указанием ее временных логов.

-Вхожные данные: Название задачи, описание (можно оставить пустым), дата создания (можно оставить пустым, будут использованы текущие дата и время), дата и время начала работы над задачей, дата завершения задачи(только 1 дату и время, либо 1 и 2 даты и время).

-Валидация: длина названия задачи должна быть от 1 до 100 включительно символов, длина описания должна быть от 1 до 10000 включительно символов(если не оставлять пустым), если указана дата создания, то она должна удовлетворять "ДД.ММ.ГГГГ" (можно также указать с временем "ДД.ММ.ГГГГ ЧЧ:ММ"), нельзя создать задачу с названием, которое уже есть в таблице с задачами в записях базы данных для текущего проекта, дата создания задачи должна быть меньше даты начала таймера задачи, дата таймера начала задачи должна быть меньше даты завершения или паузы таймера.

-Результат: создание задачи с указанием ее временных логов, с перенаправлением на страницу  задач проекта или сообщение о ошибке с отсутствием действий.

-Используемые SQL-запросы: "SELECT name FROM tasks WHERE name=? AND project_id=?" (поиск названия задачи текущего проекта, чтобы убедиться, что для проекта нет задачи с данным названием);"INSERT INTO tasks(name, description, status, created_at, project_id) VALUES (?, ?, 'passive', ?, ?)" (добавление с учётом описания); "INSERT INTO tasks(name, description, status, created_at, project_id) VALUES (?, NULL, 'passive', ?, ?)" (добавление без учёта описания); "INSERT INTO time_logs (datetime_start, datetime_end, comment, duration, task_id) VALUES (?, ?, 'stop', ?, ?)" (запись временного лога и с датой и временем начала, и с датой и временем завершения); "INSERT INTO time_logs (datetime_start, comment, task_id) VALUES (?, 'start', ?)" (создание временного лога только с датой и временем начала).

-Обработка ошибок: сообщение о ошибке создания задачи из-за несоответствия условиям валидации названия, описания, даты создания, даты начала задачи, даты завершения задачи, сообщение о ошибке создания задачи при наличии задачи с таким названием у текущего проекта.

**2.7. Изменение задачи**

-Назначение: изменение выбранных данных задачи.

Входные данные(в зависимости от выбора изменямых данных): название, описание, дата создания, дата начала задачи, дата завершения.

Валидация: длина названия задачи должна быть от 1 до 100 включительно символов, длина описания должна быть от 1 до 10000 включительно символов(если не оставлять пустым), если указана дата создания, то она должна удовлетворять "ДД.ММ.ГГГГ" (можно также указать с временем "ДД.ММ.ГГГГ ЧЧ:ММ"), нельзя создать задачу с названием, которое уже есть в таблице с задачами в записях базы данных для текущего проекта, дата создания задачи должна быть меньше даты начала таймера задачи, дата таймера начала задачи должна быть меньше даты завершения или паузы таймера.

-Результат: измененние данных задачи с перенаправлением на страницу задач проекта или вывод сообщения о ошибке изменения задачи.

-Используемые SQL-запросы: "SELECT project_id FROM tasks WHERE id=?" (Выбор идентификатора текущего проекта) "SELECT name FROM tasks WHERE name=? AND project_id=?" (поиск нового названия задачи среди задач текущего проекта, чтобы убедиться, что задачи с таким названием нет) "UPDATE tasks SET name=? WHERE id=?" (Обновление названия задачи); "UPDATE tasks SET description=? WHERE id=?" (Обновление описания); "UPDATE tasks SET created_at=? WHERE id=?" (Обновление даты создания задачи); "UPDATE time_logs SET datetime_start=? WHERE id=?" (Обновления таймера начала задачи); "UPDATE time_logs SET datetime_end=? WHERE id=?" "UPDATE time_logs SET comment=? WHERE id=?" "UPDATE time_logs SET duration=? WHERE id=?"(обновление даты завершения, обновление комментария на 'stop', обновление продолжительности временного лога: дата завершения - дата начала)

-Обработка ошибок: сообщение о ошибке измененния задачи из-за несоответствия условиям валидации названия, описания, даты создания, даты начала задачи, даты завершения задачи, сообщение о ошибке изменения задачи при наличии задачи с таким названием у текущего проекта.
