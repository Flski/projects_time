**2. Описание экранов**

**2.1. Страница авторизации (docs/login.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/login.png

-Назначение: ввод данных логина и пароля для авторизации, возможность перехода на страницу регистрации.

-Элементы управления: поле ввода для логина, поле ввода для пароля, кнопка для входа(активация POST запроса), ссылка на страницу по адресу регистрации.

-Данные на экране: статические данные, информирующие о назначении элементов интерфейса страницы, сообщения о ошибках.

-Действия пользователя: ввод логина, пароля, вход при введенных логине и пароле, переход по ссылке на адрес регистрации

-Реакции системы: при переходе по ссылке регистрации осуществляется запрос по url-адресу регистрации учётной записи; при введении логина и пароля, нажав на кнопку войти(активировав POST запрос), пройдя валидацию, указав верно логин и пароль(логин есть в таблице с пользователями базы данных, а пароль проходит функцию проверки по хэшу в базе данных), создаётся токен с логином пользователя (он хранится в .sub), данные сохраняются в cookies, осуществляется переход на url-адрес с списком проектов пользователя(GET запрос); при непрохождении валидации или неправильном логине или пароле система делает перенаправление на страницу авторизации (с POST запроса обратно в GET, на статическую страницу авторизации).

-Обработка ошибок: сообщение о ошибке при неверном логине или пароле, сообщение о ошибке ввода некорректных данных при несоответствии условиям валидации.

**2.2. Страница регистрации (docs/registration.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/registration.png

-Назначение: ввод данных логина и пароля для регистрации учётной записи, возможность перейти на страницу авторизации.

-Элементы управления: поле для ввода логина, поле для ввода пароля, поле для подтверждения пароля, кнопка для создания учётной записи (активации POST запроса), ссылка на адрес авторизации.

-Данные на экране: статические данные, информирующие о назначении элементов интерфейса страницы, сообщения о ошибках.

-Действия пользователя: ввод логина, пароля, подтверждения пароля, регистрация при введенных логине, пароле, подтверждающего пароля, переход по ссылке на адрес авторизации.

-Реакция системы: при переходе по ссылке авторизации происходит обработка GET запроса по url-адресу авторизации; при введении логина, пароля и подтверждающего пароля, нажав на кнопку "Регистрация" (активировав POST запрос), пройдя валидацию, при отсутствии записей с таким же логином в таблице с пользователями в базе данных, создаётся хэш пароля, данные добавляются в базу данных, происходит перенаправление по url-адресу авторизации (GET запрос); при непрохождении валидации или наличии пользователя с введенным логином происходит перенаправление на url-адрес регистрации (с POST запроса на GET обратно).

-Обработка ошибок: при непрохождении валидации сообщение о некорректных данных, при наличии введенного логина в записях таблицы с пользователями в базе данных сообщение о том, что логин занят.

**2.3. Страница с проектами пользователя (docs/projects.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/projects.png

-Назначение: просмотр списка проектов с их датой создания, названием, описанием (предосмотр), статусом, количеством задач. Возможность перейти на url-адрес для просмотра проекта (с полным описанием), а также перейти на url-адрес со списком задач данного проекта. 

-Элементы управления: навигация с выпадающим списком (учётная запись, список проектов, добавление проекта, выход из учётной записи), ссылка для перехода на страницу просмотра проекта, ссылка на страницу списка задач проекта. 

-Данные на экране: данные из таблицы с проектами в базе данных (проекты пользователя).

-Действия пользователя: переход по ссылке проекта для его просмотра, изменения или удаления, переход по ссылке на адрес списка задач проекта.

-Реакция системы: SELECT запрос в базу данных для получения проектов пользователя, обработка url-адреса конкретного проекта (GET-запрос), обработка url-адреса списка задач проекта (GET-запрос).

**2.4. Страница с задачами проекта (docs/tasks.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/tasks.png

-Назначение: просмотр списка задач для определенного проекта пользователя, возможность перехода на страницу конкретной задачи, использовать функционал таймера задачи.

-Элементы управления: навигация с выпадающим списком, ссылка для перехода на страницу конкрентной задачи, кнопки старт, пауза, завершить.

-Данные на экране: данные из таблицы с задачами в базе данных (задачи проектов пользователя).

Действия пользователя: переход по ссылке на конкретную задачу, использование кнопок таймера(старт, стоп, завершить).

-Реакция системы: SELECT запрос в базу данныз для получения задач проекта пользователя, обработка url-адреса конкретной задачи, активация POST-запроса при нажатии на кнопку старт, пауза или завершить (запись или обновление данных в таблицу временных логов в базе данных)

**2.5. Страница создания проекта (docs/new_project.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/new_project.png

-Назначение: создание проекта с указанием его названия, описания (не обязательно), даты (не обязательно).

-Элементы управления: навигация с выпадающим списком, поле для ввода названия, поле для ввода описания, поле для ввода даты, кнопка для создания проекта.

-Данные на экране: статические данные (форма для создания проекта).

-Действия пользователя: ввод данных в поля ввода, использование кнопки создания проекта.

-Реакция системы: активация POST запроса, валидация названия, даты(при наличии), описания(при наличии), при отсутствии среди проектов текущего пользователя проектов с таким же названием создание записи в базе данных, перенаправление на url-адрес со списком проектов, иначе перенаправление с POST запроса страницы создания проекта на GET запрос по данному url.

-Обработка ошибок: сообщение о наличии проекта с таким же названием у пользователя, сообщение о некорректных введенных даты и времени.

**2.6. Страница изменения проекта (docs/update_project.png)**

URL: https://github.com/Flski/projects_time/blob/main/docs/update_project.png

-Назначение: изменение данных имеющегося проекта.

-Элементы управления: навигация с выпадающим списком, поле для ввода нового названия, поле для ввода нового описания, поле для ввода новой даты создания, кнопка изменения проекта.

-Данные на экране: в полях для ввода находятся актуальные данные проекта (название, описание, дата).

-Действия пользователя: ввод новых данных проекта в поля ввода (или изменение имеющихся), использование кнопки изменения проекта.

-Реакция системы: активация POST запроса, валидация данных из полей ввода (название, описание, дата), обновление при наличии измененний относительно исходных данных, при изменении имени проерка на не наличие у пользователя проектов с данным именем, обновление записи в таблице с проектами в базе данных.

-Обработка ошибок: сообщение о ошибке изменнения проекта при неккоректном вводе даты и времени, при наличии проекта с таким названием для текущего пользователя.

**4. Сценарии взаимодействия**

**4.1. Регистрация и авторизация**

-Экраны: страница регистрации, авторизации, страница с проектами.

-Действия на страницах: ввод логина, пароля, подтверждающего пароля и использование кнопки регистрации на странице регистрации; ввод логина, пароля и использование кнопки авторизации на странице авторизации.

-Данные ввода и вывода: в формы регистрации и авторизации вводятся данные для создания учётной записи и ее проверки соотвесвенно, на странице с проектами содержатся проекты авторизованного пользователя.

-Реакция системы: обработка POST запросов авторизации и регистрации, перенаправление на url адрес с проектами пользователя (GET запрос).

**4.2. Создание проекта, просмотр созданного проекта**

-Экраны: страница с проектами, страница создания проекта, страница просмотра проекта.

-Действия на страницах: переход по ссылке в навигации по url адресу создания проекта, ввод названия, описания, даты создания, использование кнопки создания проекта; фильтрация по убыванию даты на странице с проектами, переход по ссылке просмотра проекта на странице с проектами; возможность полностью просмотреть название, дату и описнаие проекта, также удалить проект или перейти по адресу его изменения на странице просмотра проекта.

-Данные ввода и вывода: в форме создания проекта вводятся данные нового проекта, на странице с проектами данные всех проектов пользователя, на странице просмотра проекта все данные проекта.

-Реакция системы: обработка POST запроса создания проекта, перенаправление на страницу с проектами пользователя, обработка GET запросов по url адресу страницы с проектами пользователя и url адрессу с данными проекта.

**4.3. Создание задачи, просмотр задачи**

-Экраны: страница с проектами пользователя, страница создания задачи, страница с задачами проекта, страница просмотра задачи.

-Действия на страницах: на странице с проектами переход по ссылке создания задачи для определенного проекта, на странице создания задачи ввод названия задачи, описания, даты создания, даты старта, даты завершения с использованием кнопки создания задачи, на странице с задачами проекта фильтрация задач по убыванию даты, переход по ссылке просмотра задачи, на странице просмотра задачи есть возможность полностью посмотреть данные задачи, удалить ее, перейти на страницу изменения данной задачи.

-Данные ввода и вывода: на странице с проектами находятся проекты пользователя, в форме создания задачи данные новой задачи на странице создания задачи, на странице с задачами все задачи проекта пользователя, на странице просмотра задачи навание, дата старта, завершения, создания задачи.

-Реакция системы: обработка POST запроса создания задачи, перенаправление по url адресу с задачами проекта (GET-запрос), обработка GET-запроса просмотра задачи.

**4.4. Изменение пароля**

-Экраны: страница учётной записи, страница изменения пароля.

-Действия на страницах: переход по ссылке изменения пароля на странице учётной записи, ввод текущего пароля и нового пароля с ипсользованием кнопки изменения пароля на странице изменения пароля.

-Данные ввода и вывода: на странице учётной записи логин авторизованного пользователя, на странице изменения пароля ввод текущего и нового паролей в форму изменения пароля.

-Реакция системы: обработка GET-запроса страницы учётной записи, обработка POST запроса изменения пароля, перенаправление на по url адресу учейтной записи (GET-запрос).
