1. **Общие сведения**

   1.1. Название программного продукта: Трекер рабочего времени, потраченного на задачи и проекты.

   1.2. Краткое описание: Данный программный продукт (десктопное приложение) позволяет создавать и изменять проекты и задачи, вести их историю, формировать на их основе общее рабочее время. Данное приложение позволит отслеживать текущий статус проектов или задач, что является полезным для соблюдения сроков текущих проектов или задач, а также является удобным для пользователя с большим количеством задач или проектов.

   1.3. Целевая аудитория: Данный проект разрабатывается для индивидуального использования разработчиком для отслеживания текущих задач, связанных с учёбой, а также задач и пет-проектов, связанных с будущей профессией.

2. **Функциональные требования**

   2.1. Обязательные требования (MVP): 

-Регистрация пользователей.

-Авторизация пользователей с отсутствием доступа к функционалу приложения без авторизации.

-Создание, чтение, изменение и удаление задач и проектов.

-Использование текущих даты и времени для начала проекта и задачи и их завершения (таймер).

-Добавление проектов и задач вручную с указанием времени и даты начала.

-Ведение истории задач и проектов с формированием времени, затраченного на проект или задачу.

-Фильтрация по датам (по дате начала времени, затрачиваемым на проект или задачу) в истории проектов и задач.

2.2. Дополнительные требования:

-Создание хэша паролей.

-Удаление учётной записи вместе с задачами и проектами пользователя.

-Изменение вручную даты начала, даты окончания, названия, описания проекта или задачи.

-Создание проектов и задач с указанием и даты начала, и даты завершения (создание уже завершенных проектов или задач).

**3. Нефункциональные требования**

-Язык интерфейса: русский.

-Производительность: время отклика интерфейса — не более 1 секунды при стандартных операциях.

-Хранение данных: локально в файле БД (SQLite), сеть не используется.

-Защита от ошибок: нельзя сохранить рецепт без названия, нельзя указать отрицательное количество ингредиента, нельзя удалить ингредиент, который используется в рецепте (без подтверждения).

-Инициализация БД: при первом запуске приложение само создаёт таблицы из встроенного SQL-скрипта.

-Лаконичный интерфейс с использованием не более 4 цветов.

-Главная страница включает список с проектами и задачами с элементом интерфейса для фильтрации, кнопка для перехода в раздел управления учётной записью (в котором элементы интерфейса для удаления учётной записи, изменение логина), кнопка для переход в раздел добавления проекта и задачи (в котором можно выбрать: создание с указанием заголовка, описания; создание с указанием заголовка, описания, даты начала; полное создание с учётом всех предыдущих данных с датой и временем завершения), также через элементы списка задач и проектов можно перейти на раздел их изменения.

**4. Модель данных **

-Так как приложение ориентировано на индивидуальные данные пользователя.  Таблица с пользователями – clients; id (Первичный ключ) имеет целочисленный тип данных INTEGER, login и password (логин и пароль пользователя) имеют строковый тип данных TEXT.

-Таблицы tasks и projects с задачами и проектами пользователя соответственно: id (первичный ключ) имеет целочисленный тип данных INTEGER, title и description (заголовок и описание проекта, задачи) имеют строковый тип данных TEXT, begin_datetime и end_datetime (время начала и завершения) имеют строковый тип данных TEXT, так как в SQLite отсутствует полноценный тип данных даты и времени(строка будет преобразована к datetime типу данных при SELECT запросах для вычисления разницы времени). user_id (Внешний ключ) имеет целочисленный тип данных INTEGER, ссылается к таблице clients, к id.

-Связь между clients и tasks – 1:M (1 ко многим), clients и projects – 1:M (1 ко многим).

**6. Сценарии использования**

-Авторизация. Пользователь вводит логин и пароль, логин есть в базе данных, а пароль прошёл проверку функции или метода для проверки хэша пароля с введённым паролем – авторизация, переход в главное меню приложения, иначе вывод ошибки о неверном логине или пароле, пользователь не авторизован.

-Добавление задачи или проекта. Пользователь вводит в поле ввода заголовок, описание задачи или проекта (также возможно ручное добавление даты и времени начала и завершения), если проекта или задачи с таким же заголовком нет в базе данных для данного пользователя, если длина всех одних введенных данных не равна 0 (описание может быть пустым), если  введенные данные не пробелы, то задача или проект создастся с выводом сообщения о создании, иначе сообщение о ошибке создания проекта или задачи.

-Просмотр истории проектов и задач. Пользователь переходит в историю проектов и задач, при наличии их выводятся все задачи и проекты, с сокращенным описанием (определенная длина для уменьшения размеров элемента интерфейса), заголовком, датой начала, датой завершения (при наличии), типом (задача, проект), время проекта или задачи(разность текущего времени с временем начала задачи или проекта, при наличии даты и времени завершения разность даты и времени завершения и даты и времени начала проекта или задачи), статистика общего времени работы с проектами и задачами (общая статистика вне списка задач и проектов), элементы интерфейса для фильтрации по возрастанию, убыванию даты начала, по уменьшению, увеличению времени над проектом или задачи.

**7. Критерии приёмки**

-Авторизация не позволяет иметь доступ к функционалу приложения для пользователей (управление задачами и проектами).

-В базе данных хранятся хэши паролей, а не сами пароли.

-Регистрация не позволяет создать пользователя с логином, который уже есть в базе данных.

-Интерфейс авторизации и регистрации лаконичный, содержит не более 4 цветов.

-Есть вывод ошибок для авторизации и регистрации.

-Невозможность создать проект с заголовком, который уже есть в записи базы данных для данного пользователя.

-Невозможность создать задачу с заголовком, который уже есть в записи базы данных для данного пользователя.

-Корректное обновление даты начала, даты завершения, заголовка, описания задачи.

-Корректное обновление даты начала, даты завершения, заголовка, описания проекта.

-Корректное удаление проекта и задач.

-Интерфейс меню, окна добавления задачи и проекта, окна изменения задачи и проекта является лаконичным, содержит не менее 4 цветов.

-Текущие дата и время, даты и время начала, завершения задачи или проекта являются достоверными.

-Корректное удаление пользователя с удалением его задач и проектов.

-Фильтры по дате работают корректно.
