**Бриф на разработку программного продукта**


**1.Общие сведения**

**1.1. Название программного продукта:** Веб-приложение для учёта времени, потраченного на задачи и проекты.

**1.2. Описнание программного продукта:** Данное веб-приложение формирует общее время работы над проектом. Оно имеет возможность создать проект, создать задачи для данного проекта, для каждой задачи использовать таймер, - данные функции позволяют пользователю определять время работы с задачами и в целом с проектом. Программный продукт решает проблему отсутствия учёта времени, которое используется для работы с задачами и проектами в определенных сферах деятельности.

**1.3. Целевая аудитория:** Целевой аудиторией данного программного продукта являются пользователи, которые имеют проектную деятельность. Студенты могут использовать данное веб-приложение для курсовой работы, школьники для подготовки к экзамену, для специалистов, имеющих определённые проекты, данное веб-приложения является важным в условиях непонимания, сколько времени занимают задачи, какова общая продолжительность проекта.

**2. Функциональные требования**

**2.1. Обязательные функциональные требования:**

-Регистрация учётной записи.

-Авторизация пользователей.

-Создание, чтение, изменение и удаление проектов и задач.

-Таймер для задач с функцией старта, паузы, завершения.

-Создание задачи с указанием даты начала и завершения.

-Изменение даты и времени начала задач.

-Общее время работы проекта и задачи.

-Фильтрация проектов по возрастанию и убыванию даты (последние проекты, прошлые проекты).

-Фильтрация задач проекта по возрастанию и убыванию даты (последние задачи, прошлые задачи)

-Отслеживание статуса проекта (активный, завершение).

-Отслеживание статуса задач (активный, пауза, завершение).

**2.2. Дополнительные трбования:**

-Изменение логина учётной записи.

-Удаление учётной записи.

-Статистика активности пользователя (продолжительность проектов) по дням, неделям, годам.


**3. Нефункциональные требования:**

-Язык интерфейса: русский.

-Время отклика интерфейса не более 1 секунды для стандартных операций.

-Хранение данных локально в файле базы данных (Система управления базой данных SQLite).

-Невозможность ввести пустое название проекта, задачи, пустой логин или пароль при регистрации (определённой длины).

-Лаконичный интерфейс с использованием не более 4 цветов.

-Хранение пароля в виде хэша в базе данных.

-При первом запуске веб-приложения, при отсутствии таблиц или файла базы данных автоматизированное создание таблиц базы данных.

**4.Модель данных (файл "db.png" в данном репозитории)**

-В таблице clients содержатся данные о пользователе(логин и хэш пароля со строковым типом данных). id имеет целочисленный тип данных и явялется первичным ключом.

-В таблице projects содержатся данные о названии, описании, статусе, дате и времени создания проектов(строковый тип данных). id имеет целочисленный тип данных и явялется первичным ключом.
user_id имеет целочисленный тип данных и является внешним ключом, необходим для связи с таблицей users.

-В таблице tasks содержатся данные о названии, описании, статусе, дате и времени создания задачи(строковый тип данных). id имеет целочисленный тип данных и явялется первичным ключом. project_id имеет целочисленный тип данных и является внешним ключом, необходим для связи с таблицей projects.

-В таблице time_logs содержатся содержатся дата и время начала, завершения задачи, комментарий, продолжительность задачи. id имеет целочисленный тип данных и явялется первичным ключом. task_id имеет целочисленный тип данных и является для внешним ключом, необходим для связи с таблицей task.

-Использование строкового типа данных для даты и времени обусловлено отсутствием полноценного типа данных даты и времени в SQLite, данные будут преобразованы из строкового типа и обратно независимо от СУБД.

-Между таблицами users projects связь 1 ко многим (у пользователя есть проекты), между таблицами projects tasks связь один ко многим (для проекта есть определенное количество задач), между таблицами tasks time_logs связь 1 ко многим (у задач есть показатели времени и даты).

**6. Сценарии использования:**

-Регистрация. Пользователь вводи в форму логин, два раза пароль для подтверждения, если логин больше или равен 4, и пароль больше или равен 8 символам, и пароли совпадают, и в базе данных отсутствует пользователь с таким же логином, то происходит перенапрвление на авторизацию с сообщением о успешной регистрации, иначе (если не данные не прошли через валидацию) выводится сообщение о ошибке регистрации, оставаясь в адресе регистрации.

-Авторизация. Пользователь вводит в форму логин и пароль, если логин больше или равен 4, и пароль больше или равен 8 символам, и логин сошелся с логином из базы данных, пароль прошел функцию проверки хэша, то данные авторизации сохраняются в cookies, пользователь перенаправлен в главное меню веб-приложения, иначе (если не данные не прошли через валидацию или пароль неверный) выводится сообщение о ошибке авторизации, оставаясь в адресе авторизации.

-Создание проекта. Пользователь создаёт проект, указывая в форме его название, описание, если длина названия не равна нулю, и проекта с таким названием у пользователя нет, то проект создаётся с выводом сообщения о создании, иначе (при непрохождении валидации или наличии проекта с таким названием) вывод ошибки создания проекта.

-Изменение проекта. Пользователь переходит по адресу изменения проекта, меняет название, описание, при прохождении валидации проект изменяется, иначе вывод ошибки изменнения проекта.

-Удаление проекта. Пользователь переходит по адресу удаления проекта, удаляет его.

-Создание задач. Пользователь переходит по адресу списка задач определенного проекта, переходит по адресу создания задачи с выбором ручного заполнения даты начала и завершения или автоматического только с указанием названия и описания задачи, при прохождении валидации и отсутствии у пользователя задачи с таким же названием задача создаётся с сообщением о создании задачи, инчае (при непрохождении валидации или наличии задачи с таким названием у пользователя) вывод ошибки создания задачи.

-Изменение задачи. Пользователь переходит по адресу изменения задачи, вводит в форму новые название, описание, дату и время начала, завершения, при прохлждении валидации вывод сообщения об успешном изменении, иначе вывод ошибки изменения задачи.

-Включение, пауза и выключение таймера задачи. Пользователь переходит на задачу (со статусом бездействия или активной) проекта, включает таймер(время начала работы зафиксировано), ставит на паузу (время фиксируется и является конечным), пользователь возобновляет таймер(новый цикл, стартовое время), пользователь останавливает таймер задачи(конечное время), задача переходит в статус завершенной, сумма всех разности всех циклов начала и завершения задачи является продолжительностью задачи.

-Просмотр информации, сформированной на основе данных пользователя. В главном меню в списке проектов пользователь отслеживает название проекта, дата создания, статус, общее время работы над проектом. В списке задач проекта пользователь отслеживает название задачи, дату создания, дату начала работы над ней(при наличии), дату завершения (при наличии), продолжительность (при наличии).
